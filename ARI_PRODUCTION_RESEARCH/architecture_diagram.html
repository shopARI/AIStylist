Agent Battle Flow (Step-by-Step)

1User Request
FastAPI receives chat request with message, user_id, session_id. Request validated via Pydantic models.
2Session Management
Application Service retrieves user context from Redis cache or creates new session. Conversation history loaded.
3Intent Detection
NLP Intent Detector analyzes query. Parameter Extractor identifies filters, preferences, constraints.
4Intelligence Gathering
ML Intelligence Coordinator activates 4 systems in parallel: Behavioral RFM, Clustering, Visual PyTorch, Memory RAG.
5Battle Initialization
Battle Orchestrator creates unique battle ID, tracks in Redis, initializes semaphore for concurrency control (max 50 battles).
6Agent Deployment
CypherBot and VibeBot deployed via CAMEL Factory. Each receives ML intelligence packet and user context.
7Parallel Search
CypherBot: Constructs Neo4j Cypher queries using graph relationships and behavioral patterns.
VibeBot: Performs Qdrant vector search using embeddings and visual features.
8Judge Evaluation
Judge Ari (CAMEL agent) evaluates both result sets. Determines strategy: Cypher-dominant, Vibe-dominant, Balanced, Consensus, or Quality.
9Winner Selection
Based on strategy, Judge selects final products. Adds metadata: winning_agent, selection_reason, final_rank, judge_score.
10Response Assembly
Final response assembled with products, battle metadata, processing time. Background tasks update Redis cache and user interactions.
11Cleanup & Metrics
Battle ID removed from Redis active set. Metrics recorded: battle time, winner, ML enhancement, cache performance.
12API Response
JSON response returned to client with recommendations, session continuity, and performance metadata.
