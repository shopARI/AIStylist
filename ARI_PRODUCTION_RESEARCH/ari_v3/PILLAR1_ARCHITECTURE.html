Key Decision: How Active Context is Selected

Function: _select_active_context(query_context, detected_contexts, onboarding_profile)

Why this matters: Users have different style positions in different contexts (work vs weekend). Selecting the right context determines which position and trajectory we use for recommendations.
# Priority order (first match wins): 1. Explicit Context - User said "for work" in query if query_context.explicit_context: return it 2. Occasion Mapping - Map "wedding" -> FORMAL, "gym" -> ACTIVE if query_context.occasion: map to StyleContext 3. Onboarding Occasions - User's important occasions from onboarding sorted by importance, pick first that has interaction history 4. Most Frequent - Context with most interactions return detected_contexts[0] 5. DEFAULT - Fallback when nothing else applies

StyleContext: The 8 User Contexts

CASUAL weekend, brunch, errand User looking for weekend outfit
EVENING date, dinner, party User shopping for date night dress

ACTIVE gym, workout, hiking, sport, fitness User looking for gym clothes
CREATIVE art, gallery, concert User going to art gallery opening
TRAVEL travel, vacation, trip User packing for vacation
DEFAULT (fallback) Context unclear from query

Cold Start: When User Has No History in a Context

Function: _compute_cold_start_position(raw_data, context)

Problem: User asks for "wedding outfit" but has never shopped for formal wear before. We need to generate a position without interaction history.
# Blend available signals with weights: Signal 1: Onboarding Style weight = 0.3-0.4 taste.style_loves + taste.style_wants + brands "Loves: clean lines. Wants: bolder choices. Brands: [Everlane, Cos]" Signal 2: Social Embeddings weight = 0.5 Pinterest/Instagram taste embedding (if connected) Richest signal when available Signal 3: Population Centroid weight = 0.2 Average embedding for this context (precomputed) Currently placeholder - returns zero vector Output: blended_embedding = normalize(sum(signal * weight)) confidence = 0.3 (low - it's a cold start)

Embedding Blending: Interactions + Social

Function: _compute_unified_embeddings(interaction_embeddings, social_embeddings, user_weight)

Key Insight: New users should rely more on social signals (Pinterest/Instagram). As they build interaction history, we trust their actual behavior more.
interaction_confidence = min(1.0, interaction_count / 30) # 30 interactions = full confidence social_weight = (1 - interaction_confidence) * 0.5 # New user (0 interactions): social_weight = 0.5 (50%) # Established user (30+ interactions): social_weight = 0 (0%) interaction_weight = 1.0 - social_weight unified_embedding = normalize( interaction_embedding * interaction_weight + social_embedding * social_weight )

New User (5 interactions)

  • Confidence: 0.17 (5/30)
  • Social weight: 42%
  • Interaction weight: 58%

Established User (50 interactions)

  • Confidence: 1.0 (capped)
  • Social weight: 0%
  • Interaction weight: 100%

Common Questions

Q: Why per-context positions instead of one global position? V

Users dress differently for different occasions. Someone might be minimalist for work but bold for evening events. A single position would blur these differences. Per-context positions let us recommend work clothes based on work history, not weekend shopping behavior.

Q: What if user asks "show me dresses" with no context? V

We fall back through the priority chain:
1. No explicit context
2. No occasion keyword
3. Check onboarding occasions sorted by importance
4. Use most frequent context from their history
5. DEFAULT if nothing else

This means an active professional shopper would see professional-leaning dresses, while someone who mostly shops casually would see casual dresses.

Q: How does trajectory work? V

Trajectory tracks how user's style is evolving:

Direction: Vector showing which way they're moving in style space (recent - historical)
Velocity: How fast they're changing (0-1)
Consistency: How stable is this direction (0-1)

High velocity + high consistency = user is intentionally evolving their style
Low velocity = user has stable preferences
Low consistency = user is exploring/experimenting

Q: Why sort onboarding occasions by importance? V

During onboarding, user tells us about occasions in their life (work meetings, date nights, etc.) and rates their importance (0-1). When falling back to onboarding occasions, we want to pick the one that matters most to them, not just the first one listed. A user who rated "work" at 0.9 and "gym" at 0.3 should default to work context, not gym.

Q: What's the confidence value used for? V

Confidence (0-1) indicates how much we trust the computed position:

High confidence (>0.7): Many interactions, stable patterns - trust behavior heavily
Low confidence (<0.3): Few interactions or cold start - blend in more social signals and population priors

Formula: confidence = min(1.0, interaction_count / 30)
30 interactions = full confidence
